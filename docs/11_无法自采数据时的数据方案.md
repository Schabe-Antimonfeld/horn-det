# 11 无法自采数据时的数据方案

## 1. 问题拆分

“鸣笛识别数据”和“阵列定位数据”不必来自同一个数据集。

### 识别

只需要：

```text
音频 + horn/non-horn label
```

可用 HornBase 启动分类开发，但需按第 07 章处理双声道、重采样及来源分组，并核查短窗口是否真正包含鸣笛。

### 定位

需要：

```text
多通道同步音频 + 精确 DOA label
```

如果无法自采，可以仿真生成。

## 2. HornBase 用途

HornBase 提供 1080 个 1 秒片段，可用于：

- Tiny CNN 参考基线及第 07 章待确定分类器的训练/评价；
- horn 频谱统计；
- Horn-aware 权重 W_H[k] 估计。

但它不是你们 8-Mic UCA 的空间数据，因此不能直接训练 TDOA/DOA 网络。

HornBase 为 44.1 kHz、16 bit 双声道 WAV，来自车内手机；同一鸣笛的不同裁剪窗口及不同设备录音需归入同一数据划分。UrbanSound8K 可作为第 07 章的待确定数据补充，使用前核查官方折划分、来源关系和许可。公开录音分类、仿真阵列定位和真实路侧阵列验证应分别报告。

## 3. 最简单的远场仿真

给定单声道 horn s[n] 与方向 θ。

这里的单声道是仿真输入，不是 HornBase 原始格式。使用双声道片段时，可固定选择其中一个通道，再重采样到仿真采样率；记录通道和来源，避免未知相位差导致直接时域相加相消。分类用的多通道功率谱平均不等同于一条单声道波形。

公开录音可能已经含有噪声和混响，可用于几何流程验证；不能在再次加噪或卷积 RIR 后将其声学条件视为完全受控的干净源仿真。

对每个麦克风：

$$
\tau_m(\theta)
=
-\frac{\mathbf r_m^T\mathbf u(\theta)}{c}
$$

采样延迟：

$$
d_m=f_s\tau_m
$$

用分数延迟滤波器得到：

$$
x_m[n]
=
s[n-d_m]
$$

再加入独立或相关背景噪声。

上述 tau_m 是相对于阵列中心的延迟，可为负；各对差值仍满足第 02 章的 tau_ij=tau_i-tau_j。离线生成需保留前后边界，使用分数延迟滤波；若实现要求因果延迟，可给所有通道增加相同的公共延迟，不改变 TDOA。不能用循环移位把片段末尾音频卷回开头。

这套方法可以快速验证 GCC/SRP 的几何正确性。

## 4. RIR 仿真

更真实时使用 room impulse response：

$$
x_m[n]
=
s[n]*h_m[n]+v_m[n]
$$

随机：

```text
source angle
source distance
reflection coefficient
RT60
SNR
mic gain error
mic position error
sound speed
```

## 5. Domain Randomization

为了避免网络或参数只适应理想仿真，可以随机：

```text
麦克风位置 ±1~3 mm
增益误差 ±2 dB
固定时延 ±0.2 sample
声速 330~355 m/s
SNR -10~30 dB
部分通道失效
随机 EQ
```

## 6. 对比赛报告的表述

如果没有真实道路自采数据，应明确写：

> 算法开发和定量评价以公开数据与仿真多通道数据为主，现场演示用于功能验证，不将仿真结果等同于目标道路环境的最终部署性能。
