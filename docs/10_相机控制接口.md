# 10 相机控制接口

## 1. 当前范围

本项目暂不使用 YOLO。

相机模块只执行：

```text
接收声学方位
→ 转向
→ 抓拍
```

## 2. 声学模块输出

```text
event_state      2 bit
horn_valid       1 bit
doa_valid        1 bit
horn_probability 16 bit unsigned Q0.16
azimuth          16 bit signed Q9.7
doa_confidence   16 bit unsigned Q0.16
timestamp        64 bit unsigned us
event_id         32 bit unsigned
```

以下为本项目建议协议，正式实现前由算法与 FPGA/相机负责人共同冻结：

- event_state 编码为 0=IDLE、1=CANDIDATE、2=CONFIRMED、3=END；horn_valid 仅在 CONFIRMED 时为 1，不能代替事件状态。
- doa_valid 表示当前定位通过有效性检查，与 horn_valid 独立。doa_valid=0 时 azimuth、doa_confidence 均编码为 0，接收端不得将此当作有效的 0° 方向。
- horn_probability 是最近一次有效 CNN 的 horn 概率；尚无有效推理时用 0 占位，不能据此宣称已完成分类。CNN 确认规则见第 07 章。
- azimuth 的解码值为 signed_code/128 度；阵列坐标沿用第 02 章，0° 指向 +x，正角从 +x 转向 +y。云台方向约定不同则在控制层转换。
- doa_confidence 按第 05 章将 PSR 映射到 0~1，表示工程评分而非正确率。概率/置信度按第 09 章编码，解码为 unsigned_code/65536；1 饱和为 65535。
- timestamp 使用统一单调时钟，表示本条决策所用最新音频帧最后一个采样点的采集时间，不是消息发送时间或事件起始时间。微秒转换向下取整，固定采集链路延迟需明确标定。
- 在进入 CANDIDATE 时分配 event_id，同一事件中保持不变；无活动事件的 IDLE 使用 0。事件结束后发送 END，即使候选未被确认也应结束该事件。

每条消息中的状态、定位及置信度需对应同一决策帧；不能用新帧状态配旧帧方向。异步 CNN 结果需关联其输入结束帧，再与对应定位结果融合。传输字节序、字段打包、时钟同步及断线恢复属于接口实现配置，需在联调前约定。

## 3. 安装偏角标定

如果阵列 0° 与相机 pan=0° 存在固定偏角：

$$
\theta_{camera}
=
\theta_{acoustic}+\theta_{offset}
$$

offset 可通过在多个已知方向放置扬声器后求平均误差得到。

该加法假设声学与云台角度的正方向一致；若云台正方向相反，先转换符号再加偏角。角度归一化并检查云台机械范围；目标不可达时报告状态，不能静默截断后宣称已对准。

## 4. 状态机

```text
IDLE
 ↓
CANDIDATE
 ↓
CONFIRMED
 ↓
END
```

未确认候选取消或超时也进入 END，END 后回到 IDLE。状态转换规则与第 07 章一致。

推荐动作：

```text
CANDIDATE + doa_valid → 相机可提前转向
CONFIRMED + doa_valid + confidence threshold → 执行正式抓拍
END       → 保存事件
```

提前转向门限和抓拍门限在验证/联调阶段确定并固定。定位无效时仍可记录已确认鸣笛，但不按无效角度转向或触发定向抓拍；同一 event_id 的重复消息不能重复触发同一次抓拍。

## 5. 为什么要时间戳

即使没有车辆检测，也应对齐：

```text
音频事件时间
相机抓拍时间
```

后续复盘错误时才能判断：

- 是定位错误；
- 是云台响应过慢；
- 还是事件确认延迟过大。

除协议中的音频帧时间，还需记录候选/确认消息输出、相机接收、转向到位和实际曝光时间。事件起始时间由评价标注或单独的事件记录提供，不能用 timestamp 代替。相机与声学系统使用不同时钟时应测量时钟偏移和漂移；未同步的时间不能直接相减作为端到端延迟。
