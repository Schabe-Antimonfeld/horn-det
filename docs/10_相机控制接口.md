# 10 相机控制接口

## 1. 当前范围

历史单云台参考基线不包含车辆检测器。新增固定多相机研究原型见第 6～12 节：先验证几何、声学候选和外部车辆框关联，真实视觉模型尚待选型；不将合成框称为 YOLO 或其他检测器的结果。

历史基线的相机模块只执行：

```text
接收声学方位
→ 转向
→ 抓拍
```

## 2. 声学模块输出

```text
event_state      2 bit
horn_valid       1 bit
doa_valid        1 bit
horn_probability 16 bit unsigned Q0.16
azimuth          16 bit signed Q9.7
doa_confidence   16 bit unsigned Q0.16
timestamp        64 bit unsigned us
event_id         32 bit unsigned
```

以下为本项目建议协议，正式实现前由算法与 FPGA/相机负责人共同冻结：

- event_state 编码为 0=IDLE、1=CANDIDATE、2=CONFIRMED、3=END；horn_valid 仅在 CONFIRMED 时为 1，不能代替事件状态。
- doa_valid 表示当前定位通过有效性检查，与 horn_valid 独立。doa_valid=0 时 azimuth、doa_confidence 均编码为 0，接收端不得将此当作有效的 0° 方向。
- horn_probability 是最近一次有效 CNN 的 horn 概率；尚无有效推理时用 0 占位，不能据此宣称已完成分类。CNN 确认规则见第 07 章。
- azimuth 的解码值为 signed_code/128 度；阵列坐标沿用第 02 章，0° 指向 +x，正角从 +x 转向 +y。云台方向约定不同则在控制层转换。
- doa_confidence 按第 05 章将 PSR 映射到 0~1，表示工程评分而非正确率。概率/置信度按第 09 章编码，解码为 unsigned_code/65536；1 饱和为 65535。
- timestamp 使用统一单调时钟，表示本条决策所用最新音频帧最后一个采样点的采集时间，不是消息发送时间或事件起始时间。微秒转换向下取整，固定采集链路延迟需明确标定。
- 在进入 CANDIDATE 时分配 event_id，同一事件中保持不变；无活动事件的 IDLE 使用 0。事件结束后发送 END，即使候选未被确认也应结束该事件。

每条消息中的状态、定位及置信度需对应同一决策帧；不能用新帧状态配旧帧方向。异步 CNN 结果需关联其输入结束帧，再与对应定位结果融合。传输字节序、字段打包、时钟同步及断线恢复属于接口实现配置，需在联调前约定。

## 3. 安装偏角标定

如果阵列 0° 与相机 pan=0° 存在固定偏角：

$$
\theta_{camera}
=
\theta_{acoustic}+\theta_{offset}
$$

offset 可通过在多个已知方向放置扬声器后求平均误差得到。

该加法假设声学与云台角度的正方向一致；若云台正方向相反，先转换符号再加偏角。角度归一化并检查云台机械范围；目标不可达时报告状态，不能静默截断后宣称已对准。

## 4. 状态机

```text
IDLE
 ↓
CANDIDATE
 ↓
CONFIRMED
 ↓
END
```

未确认候选取消或超时也进入 END，END 后回到 IDLE。状态转换规则与第 07 章一致。

推荐动作：

```text
CANDIDATE + doa_valid → 相机可提前转向
CONFIRMED + doa_valid + confidence threshold → 执行正式抓拍
END       → 保存事件
```

提前转向门限和抓拍门限在验证/联调阶段确定并固定。定位无效时仍可记录已确认鸣笛，但不按无效角度转向或触发定向抓拍；同一 event_id 的重复消息不能重复触发同一次抓拍。

## 5. 为什么要时间戳

即使没有车辆检测，也应对齐：

```text
音频事件时间
相机抓拍时间
```

后续复盘错误时才能判断：

- 是定位错误；
- 是云台响应过慢；
- 还是事件确认延迟过大。

除协议中的音频帧时间，还需记录候选/确认消息输出、相机接收、转向到位和实际曝光时间。事件起始时间由评价标注或单独的事件记录提供，不能用 timestamp 代替。相机与声学系统使用不同时钟时应测量时钟偏移和漂移；未同步的时间不能直接相减作为端到端延迟。

## 6. 固定多相机参数与边界

目标是在指定地面区域内选择摄像头、获取关联图像，并标出鸣笛方向上的车辆候选。唯一几何匹配仍是候选，不能单独证明具体车辆鸣笛。

世界坐标以设备底座为原点、地面 z=0、+z 向上，水平角沿用第 02 章。相机光轴相对水平面向下的俯角为 θ；θ 不表示视场角，也不表示声源俯角 β。

| 参数 | 意义 | 仿真默认值 |
|---|---|---|
| n / count | 环形相机数，另加下视 1 个 | 6 |
| h / height | 阵列及理想相机公共中心离地高度 | 6 m |
| θ / pitch | 环形相机向下俯角 | 40° |
| yaw | 第一个环形相机水平朝向 | 0° |
| hfov / vfov | 环形相机水平/垂直视场角 | 90° / 70° |
| down_hfov / down_vfov | 垂直下视相机的视场角 | 120° / 100° |
| width / image_height | 图像宽高 | 1280 / 720 px |
| minimum_range / maximum_range | 地面监控环带 | 1 / 40 m |
| horn_height | 仿真喇叭离地高度 | 0.8 m |

均匀布局朝向 ψ_i=yaw+360°i/n。各相机中心、朝向、俯角、视场和分辨率可逐个覆盖。默认值只是演示场景，n、h 尚未冻结；修改安装配置后需重新计算覆盖和标定。现有针孔模型假定无滚转、无畸变、主点位于图像中心；真实相机内参、畸变校正和完整姿态尚需接入。

## 7. 覆盖条件与投影

在光轴所在竖直截面内，若 0<θ-φ_V/2<θ+φ_V/2<90°，则：

$$
R_{near}=h\cot(\theta+\phi_V/2),\qquad
R_{far}=h\cot(\theta-\phi_V/2)
$$

公式仅给出中心截面，不能代替整片地面覆盖。视场跨越水平线或正下方时改用射线投影。理想垂直下视相机的平地矩形覆盖宽高为 2h tan(φ_DH/2)、2h tan(φ_DV/2)，内接圆半径为 h tan(min(φ_DH,φ_DV)/2)。相机偏移后应按真实中心计算。

对世界点 P，相机中心 C、世界到相机旋转 R、焦距 f_x/f_y、主点 c_x/c_y：

$$
\mathbf q=R(\mathbf P-\mathbf C),\qquad
u=c_x+f_xq_x/q_z,\qquad v=c_y+f_yq_y/q_z
$$

仅当 q_z>0 且投影在连续边界 [0,W]×[0,H] 内，才判为几何可见。原型使用 f_x=W/(2tan(φ_H/2))，f_y 同理；R 的三行是图像右、图像下、光轴前方向，构成右手坐标系。

覆盖判断检查 [R_min,R_max] 地面环带内各相机可见性的并集及重叠数；nφ_H≥360°不保证地面无盲区。原型使用 1 m 等面积网格中心采样，只报告采样覆盖率，不能证明连续地面无缝。实际还需检查遮挡、边缘标定余量和车辆像素尺寸；几何覆盖率不能当作检测召回率。

像素反投影为世界射线 C+λd，与 z=0 交点满足 λ=-C_z/d_z。像素越界、射线朝上或近似平行地面时返回无效，不强行生成地面位置。

## 8. 360°声学候选与相机选择

```text
14-ch completed PCM window
    → 360° azimuth / downward-depression SRP
    → periodic spatial peaks
    → candidate delay-and-sum beams
    → frozen PANNs horn scores
    → score gate
    → relevant ring/down cameras
```

窗口为已完成的一秒；搜索步长方位 2°、俯角 3°。逐帧 PHAT 后平均，候选以球面方向夹角至少 12°抑制重复；±180°相邻。候选数可配置，默认 2，尚未实现按实时预算动态扩展。分类阈值 0.2、最小分差 0 继承旧实验，在新场景中只是待验证的演示值，未完成新场景校准。

相机路由覆盖方位±6°扇区，采样 128 个距离和地面/喇叭/1.5 m 三个高度，选取能看到任一点的相机；边界可选多台，近处同时检查下视相机。路由是采样近似，尚无连续覆盖保证。接近正下方的方位未定义时检查全部相机，保持归属不确定。拒绝窗口不触发定向关联，不伪造 0°有效方向。

## 9. 外部车辆框与声画关联

`Detection` 输入为独立观察 ID、相机 ID、车辆框、地面接触锚点、曝光时间及可选视觉速度。锚点应属于道路接触位置，不能无条件用车框中心或底部中心替代；真实检测、锚点提取、跟踪和跨相机身份识别未在本原型实现。

1. 将接触锚点反投影到地面。
2. 用车辆位置、假定喇叭高度和声速估计飞行时间。
3. 将位置补偿到近似发射时刻，计算相对阵列的水平方向。
4. 按监控范围、时间差、水平角、俯角和空间响应筛选，保留全部兼容车辆。
5. 跨相机按地面位置聚类，不使用真值车辆 ID 参与选择。

音频窗口代表性接收时间 t_a、曝光时间 t_v、视觉位置 p_v、速度 v 满足近似关系：

$$
t_e=t_a-\frac{\sqrt{\|\mathbf p_e\|^2+(h-z_s)^2}}c,\qquad
\mathbf p_e=\mathbf p_v+\mathbf v(t_e-t_v)
$$

原型迭代 4 次求近似解；默认零速度是静止假设。窗口中心不是精确鸣笛起点，实际需结合有效声学帧和窗口内事件时间，不能靠该公式消除时间不确定性。

演示门限：方向误差≤6°，曝光相对发射时刻差≤0.5 s；跨相机距离≤0.75 m 且簇内不含同相机的两个框，采用完全连接检查避免链式扩张。门限待验证，靠近双车仍可能误合并，重复框也可能造成歧义。

### 9.1 修正：可见车辆必须解释声学证据

默认关联为 `Association(method="spatial")`；`azimuth` 仅作为显式旧基线，`depression` 作为中间消融。默认不再因为某辆车是唯一可见候选就输出 unique；缺少声学方向证据或响应网格时拒绝，不静默降级。

对距离 r 的视觉候选，使用位置半径误差 e_r=0.75 m、喇叭高度 z_s±e_h（e_h=0.5 m，截取到 [0,h]）计算理论俯角区间：

$$
\beta_{min}=\arctan\frac{h-z_{max}}{r+e_r},\qquad
\beta_{max}=\operatorname{atan2}(h-z_{min},\max(0,r-e_r))
$$

测得俯角超出该区间再扩展的±3°时，报告 depression_mismatch。例如 h=6 m、z_s=0.8 m 时，12/24 m 同方向车辆约对应23.4°/12.2°；水平角一致不代表俯角兼容。上述边界是可调工程假设，不是经过校准的误差置信区间。

spatial 模式进一步在视觉位置/高度区间对应的 SRP 网格内取最大响应 S_v，并保留半网格容差。参考 S_h 是同一音频窗口中由 PANNs 选中的鸣笛候选峰，背景参考 S_0 为整张响应图中位数：

$$
S_v\ge S_0+0.85(S_h-S_0)
$$

S_h 必须相对 S_0 有非退化对比度，否则报告无信息响应；没有覆盖的网格或响应不足时报告未匹配。不能使用可能属于发动机的全局最大峰替代 S_h。该检查复用麦克风对理论时延对应的 SRP 响应，当前实现是在方向网格上评估，不是已经实现了逐车球面波近场重算。

沿鸣笛候选水平角，统计达到上述响应水平的连续俯角区间，宽度包含一个网格步长。宽度超过12°时，即使只剩一辆兼容车，也保留 ambiguous。峰宽和0.85门限是未校准的工程评分，不代表物理分辨率、置信概率或已证明的排他归属。

| 状态 | 定义 | 标注策略 |
|---|---|---|
| unmatched | 无兼容车辆簇 | 保留原图和方向，注明未匹配 |
| unique | 一个兼容车辆簇且当前模式没有未解决的峰宽歧义 | 标为声学兼容候选，保留证据 |
| ambiguous | 多个兼容簇、方位退化或空间峰过宽 | 标出全部候选，归属待确认 |

保留“当前可见车辆都不能解释声源”选项：无兼容簇时返回 unmatched 与 source_unexplained=true，并记录缺证据、俯角不符、响应不符或图像过期等原因。该标志不证明一定发生漏检。

旧基线的反例是鸣笛车漏检后同方向另一车被错误唯一匹配。俯角及空间检查可以拒绝可分辨的不一致车辆，但两车方向差小于实际分辨能力、喇叭高度估错、PANNs选错波束或混响造成虚假峰时，仍可能无法排除错配；不把本轮零错配小样本视为道路保证。

## 10. 缓存、协议及待接入功能

实际相机应连续采集并保存带曝光时间的环形缓存，确认鸣笛后提取相关历史帧与后续帧。当前仅提供模拟观察记录和时间筛选，不实现实时视频缓存、硬件抓拍或文件传输。速度由两次模拟锚点反投影求差，不是已验证的真实跟踪器。

第 2 节 19-byte wire 继续服务旧单云台协议，不新增未经约定的字段或改变有效性。扩展用本地 JSON 保存方向、分数、相机 ID、观察 ID、框、地面位置和匹配状态。传输俯角或车辆身份需另行冻结版本化接口；本原型尚未与 FPGA/相机链路联通。

## 11. 原型与仿真执行

实现为 `prototype/src/horn/surround.py`，入口为 `prototype/simulate_surround.py`，测试为 `prototype/tests/test_surround.py`。仓库根目录执行：

```powershell
.\prototype\.venv\Scripts\python.exe -B prototype/simulate_surround.py --output prototype/outputs/surround_v2
.\prototype\.venv\Scripts\python.exe -B prototype/simulate_surround.py --geometry-only --cameras 8 --height 8 --pitch 45 --hfov 90 --vfov 70 --output prototype/outputs/surround_custom
```

也可在已有 learning 环境的 prototype 目录使用 `uv run --extra learning python simulate_surround.py ...`。不新增依赖，不下载数据或模型。`--geometry-only` 不需 PyTorch 权重；完整运行复用本地 `outputs/horn_detector_v1/` 的 PANNs、清单和原始录音，缺失则报错。

## 12. 验证边界

分离三层证据：几何覆盖、已知方向的合成框关联、真实单声道录音合成理想阵列的静止闭环。不同层不能混成实路精度。真实视觉模型、连续视频跟踪、遮挡、坡度、阵列误差、混响、移动声场、时钟同步和硬件 I/O 待完成，评价规则见第 12 章。
