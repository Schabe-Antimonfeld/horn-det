# GC2093 单颗 USB 广角摄像头适配

`legacy`固定在`1f11b16`，保留原多相机版本；`main`在该历史基础上实现单摄像头方案，未改写历史。14路、48 kHz、240 mm阵列及采集/CNN/SRP RTL沿用原实现。摄像头接PYNQ-Z2的Linux USB主机，由ARM PS处理，不接PDM引脚，不使用其板载麦克风替代同步阵列。

历史几何仿真命令和Tiny效果记录保留为来源说明，其代码已归档到codex/archive-2026-11-03；当前算法运行、固定权重及复现入口以[README.md](README.md)为准。

## 2. 当前处理流程：仅声学点

同步阵列 → PS全网格SRP → 候选FFT波束 → 固定BandTemporalMLP → 候选事件/严格鸣笛确认 → 声学射线与镜头投影 → 原时刻USB缓存图像 → 保存原图及候选点图。当前MLP在ARM PS，不使用Tiny CNN核或车辆检测器，不加载YOLO。

- 默认`layout=single`、`count=1`，只有`wide-0`。安装高度、yaw/pitch/roll和offset可调，默认不是实测位姿。相机中心为`(offset_x,offset_y,height+offset_z)`，阵列中心为`(0,0,height)`；世界+x为0°，+y为正方位，+z向上，pitch向下。
- 共中心时，由方向单位向量v直接投影`camera.project(array_center + v)`，结果与射线选点距离、假定车高和地面位置无关。它标的是声源方向，不是车辆底部或车体中心。非零偏移产生视差，未知距离时输出`depth_required`、保存未标点图；函数支持外部独立实测距离，但当前实时声学链路不估距离。
- `azimuth=None`且俯角未精确到90°时，方向是一圈可能射线，输出`azimuth_ambiguous`，不能用任意0°补齐。严格正下方可标图像对应中心；有roll/内参时依实际投影。多个候选各自投影、编号，保留画外分支，不能因只看见一个点就确定车辆归属。
- 使用实测K和Brown五参数或OpenCV fisheye四参数，统一原始分辨率JPEG坐标；拒绝画外、背面和镜头有效角之外的点。不需要去畸变整张图，不以商品FOV百分数代替内参。
- 可靠单窗≥0.90即有`horn_confirmed=true`，保存确认阶段声源点图。每事件/相机/阶段有界去重；释放仍用两次未达标更新；低分窗即使滞回state仍为CONFIRMED，horn_confirmed也为false。输入/前端/激活溢出不抓拍。
- 缓存图像与音频窗口代表时刻偏差超过association.maximum_skew（默认0.5 s）拒绝保存并重试。声传播、窗口内实际鸣笛时刻、设备/驱动缓冲均未完全校正；host_read_midpoint不等于曝光时间，所有图仍保留时序和车辆归属未验证说明。
- USB尺寸、FOURCC或报告FPS与请求不符即报错。spawn进程持续取流，主进程8帧JPEG缓存、采样0.25 s，约1.75 s历史。每帧上限8 MiB，另有解码/队列内存；需要实测掉帧和峰值，不宣称画点路径没有I/O成本。
- `vision={enabled:false, output:acoustic_points}`仅是相机输出开关及格式，旧model/sha256/classes等车辆模型键会被拒绝。OpenCV仍用于相机/JPEG和circle；没有readNet、forward或车辆框绘制。

## 3. 合作者操作顺序

本轮不安装OpenCV或下载模型；以下使用板上已有兼容运行库。

1. 记录Linux/PYNQ/Python/NumPy/OpenCV、USB VID/PID、V4L2格式及供电。优先MJPG和稳定`/dev/v4l/by-id/...`路径。
2. `python scripts/camera.py probe --output outputs/usb-probe`检查协商、持续帧率，再与声学并行测掉帧、gap、skipped_windows、CPU与内存。
3. `python scripts/camera.py collect --output outputs/checkerboard`采集棋盘，覆盖边角、距离及姿态；用实际内角点和米制格边长执行calibrate，保存留出误差与来源哈希。具体参数见`python scripts/camera.py calibrate --help`。
4. 配置实测内参、height/yaw/pitch/roll/offset，至少4组独立地面控制点执行`python scripts/camera.py check-ground --config CONFIG --points CONTROLS`，再检查不同角度的已知声源原图投影。低RMS不证明整个视场可靠。
5. 共中心安装须实测确认；偏移不能用0代替。明显偏移但未知声源距离时当前服务只保存无点图并记录depth_required，不能声称已解决视差。更换分辨率/裁切/镜头/对焦或位姿后重新检查。
6. 配置`vision.enabled=true`启用读图和标点；无标定或simulation_only标定会被拒绝。无需任何车辆检测模型。记录单窗0.90确认与留图、多候选、画外、未解析、时钟及误报；没有车框与车辆身份判断。

## 5. 历史：切换单窗0.90前的朝下声源点模拟（2026-11-03）

入口`scripts/simulate_downward.py`默认h=6 m、pitch=90°，构造fisheye k1=-0.035，根据144°/77.6°名义中心截线计算fx/fy，最大支持角85°。不是GC2093实测参数；车体与道路为计算生成。该轮只改相机输出模式。随后默认已改为单窗0.90；以下保留原0.95/两窗结果，新模拟按当前配置写入门限与确认窗数。

使用与旧downward_v3相同的4条公开录音、12个位置和种子，48场景各3窗。球面绝对延时、通道相对增益、强5 dB干扰和噪声生成14路PCM16；阵列中心RMS固定，不能外推SPL或绝对距离性能。

20个合成地面控制点仅检查几何：名义往返误差近零，高度+0.3 m、姿态偏2°/2°、镜头fx/fy+3%与k1+0.01、像素噪声2 px均会在地面检查中显现。直接共中心射线投影不依赖绝对高度，因此仅共同平移高度不改变点；镜头/旋转/声学方向误差仍改变点。无遮挡/隐藏目标车体代理不改变声学点，系统不知道该车是否可见，不能据此认定是哪辆车。
